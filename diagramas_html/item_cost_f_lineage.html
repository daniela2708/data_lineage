Findings

  • This cost table has been rebuilt at least eight times over the years. Only the newest copy is still active and updated this week. The other seven copies have been frozen since late 2019 or early 2020
  • The true row count is 25.76 billion, measured directly, higher than the database's own quoted statistic of 24.1 billion. Both the measured count and the age of this table, with data going back to November 2019, are extraordinary for a cost table and should be sanity checked with the Weis team before repeating in a client deliverable
  • One cost adjustment field is populated on only a small fraction of rows, effectively unused across this table's history. A related preferred-vendor field is populated on nearly all rows. The other adjustment fields checked are fully populated
  • The same pattern repeats one step earlier in the pipeline: six copies of the landing table exist, only one is active
  • Two sources write this table. One is the running load, HQ, responsible for essentially the entire table and still active today. The other, labelled COST OVERRIDE, touched a small number of rows and has been frozen since May 2023, a one time manual correction rather than an ongoing process
  • No automatic key assignment happens on insert here, unlike most dimension tables in this warehouse. That is expected: the primary key is a business key (which store, which item, which effective date), not a generated one
