Findings

  • About 74% of this table (1,615 of 2,194 rows) is placeholder data automatically generated by another process, not real operator records, and new placeholders are still being added today. The process that should load real operator records stopped working over 10 years ago (2016), despite being scheduled to run every day
  • Closer checking shows the suspected source does not fully hold up: the placeholder-creating process has a built-in default source (a POS sales transaction table) that produces a different result than what actually appears on the placeholder records, meaning some other process must be supplying the real source before it runs. This also shows the same shared template is separately used elsewhere against POS transaction data, for an unrelated purpose
  • The process that creates these placeholder records is a shared, reusable template used across several tables. The specific source it draws from for this table has not been identified
  • The likely real source of these placeholder records is WMBI.OVERRIDES_ALERTS_F (17,746,540 rows, live), based on a naming and column match. This has not been confirmed by any process explicitly linking the two tables
  • The source system for real operator records, eamtran_operator_dim, cannot be located anywhere in the Oracle environment, the same issue already found on the TX_TYPE_DIM and POS_ITEM_TYPE_DIM tables
  • Unlike every other lookup table reviewed so far in this project, this table has no generic 'unknown' placeholder row
