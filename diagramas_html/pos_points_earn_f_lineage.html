Findings

  • The process that loads this table, its staging table, or its 3 point-bucket columns has not been found anywhere in the available material
  • The three point-tier columns (BKT_10, BKT_18, BKT_20) are populated at very different rates (81%, 4%, 15%), and some rows carry more than one at once. A transaction timestamp column is populated on less than 1% of rows. What each point tier actually represents is not confirmed
  • All 282,480,232 rows are tagged with the same source platform name, 'EME'. This is the same unexplained platform name already found on SUNOCO_FUEL_PRTNR_PRGM_F and CLUB_CARD_DIM, confirmed live and current on all 3 tables: this is the third table in this project tied to this platform, which has not been identified by name anywhere in the available material
  • The staging table's name ('EARNED') does not exactly match the target table's name ('EARN'): a naming mismatch consistent with the same kind of table-rename pattern already seen on DAILY_LOC_FUEL_F
  • A near-identical sibling table, AMS_POS_POINTS_EARN_F, shares this table's exact column layout and key structure, but is a separate table with its own staging and a much larger row count (415,247,940), consistent with a POS-versus-AMS source system split already documented for this project
  • The club card reference is fully populated, and no invalid internal keys were found across all 282,480,232 rows. The full business key was not checked for duplicates, to avoid an expensive scan
