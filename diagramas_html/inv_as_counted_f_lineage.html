Findings

  • The process that loads this table has not been found anywhere in the available files.
  • Staging tables exist for center store, pharmacy and fuel counts, all confirmed live. Fresh counts have no staging table under that same naming pattern. A differently named table is a likely but unconfirmed source for fresh counts: its record count, naming and schedule all line up, but no file confirms it actually feeds this table.
  • Three separate systems feed this table, one for each type of inventory count: PICS for center store and pharmacy counts, STORE_INVENTORY for fresh counts, and VEEDER ROOT (a fuel tank monitoring system) for fuel counts. Each system's record count lines up exactly with its inventory type.
  • A separate, unrelated fresh inventory process was checked and ruled out as a source: it feeds an item master and pricing catalog for fresh items, not this table.
  • The documented business key for this table includes a cost figure rather than a purely identifying attribute. This has not been fully checked for duplicates given the table's size; the simpler primary key does hold with no duplicates found.
  • Which fields are filled in varies by inventory type, and this is a normal business pattern, not a loading gap. Center store counts carry location and retail price detail but not item description or cost. Fresh counts carry item description and cost but almost never a retail price. Pharmacy counts carry item description and cost but not location or retail price. Fuel counts have all of these fields populated.
